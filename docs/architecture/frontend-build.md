# Frontend build

The frontend is a Svelte 5 single-page app built with SvelteKit 3 on Vite. `@sveltejs/adapter-static` writes a static site to `frontend/build/`, and nginx serves it and proxies `/api/` to the backend, both in production and in the local compose stack.

## How the app starts

SvelteKit owns the entry point. `src/app.html` is the page template, and every route is served by the same fallback page, `200.html`. The root `src/routes/+layout.ts` sets `ssr = false`, so pages render in the browser only, as they did before.

`src/hooks.client.ts` runs `init` once when the app starts. It calls `initializeApiInterceptors()` from `src/lib/api-interceptors.ts`, which points the generated client at relative URLs with cookies included and registers the error toast and CSRF header interceptors. Its `handleError` logs errors from navigation, loading and rendering; SvelteKit then shows `src/routes/+error.svelte`. [Error handling](../frontend/error-handling.md) has the details.

`src/routes/+layout.svelte` imports `app.css`, applies the saved theme, initializes the auth store and renders the header, the toaster, the page and the footer. It shows a spinner instead of the page until the auth check finishes. [Routing](../frontend/routing.md) covers the routes and their guards.

`src/lib/api/` is generated by `@hey-api/openapi-ts` from `docs/reference/openapi.json` with Prettier as a post-processor. The `typescript` plugin emits types and, with `enums: 'javascript'`, runtime objects for every enum such as `UserRole`. The `sdk` and `client-fetch` plugins emit the request functions and the client, and the `zod` plugin emits a schema per model, such as `zUserCreate`, with the spec's validation rules and defaults. The schemas use `zod/mini`: classic Zod builds its faster parser with `new Function`, which the CSP blocks, while mini never tries. The client and the schemas are re-exported from the index, so everything imports from `#lib/api/index.ts`, and Zod with every schema loads with the first page. Don't edit any of it by hand. After a backend change, `./deploy.sh openapi` rewrites the spec from `create_app()` and `./deploy.sh types` runs `npm run generate:api`.

Tailwind v4 is configured in CSS through the `@tailwindcss/vite` plugin, and there is no `tailwind.config.js`. `src/app.css` imports `tailwindcss`, `styles/components.css` and `styles/pages.css`, loads `@tailwindcss/forms` with the `class` strategy, defines a `dark` variant on the `.dark` class (the theme store toggles it on `<html>`), and declares semantic color tokens such as `bg-default`, `fg-muted` and their `dark-` counterparts in `@theme`.

Shared state lives in rune-based classes in `src/stores/*.svelte.ts`, each exported as a singleton: `authStore`, `themeStore`, `notificationStore` and `userSettingsStore`. Toasts come from svelte-sonner, not a store.

## Configuration

SvelteKit 3 reads its configuration from the `sveltekit()` plugin in `vite.config.ts`; there is no `svelte.config.js`. The plugin gets `adapter-static` with `fallback: '200.html'` and the CSP:

```typescript
--8<-- "frontend/vite.config.ts:csp"
```

A per-request nonce would need a server, and SvelteKit forbids nonces on prerendered pages, so it writes the policy into `200.html` as a `<meta http-equiv="content-security-policy">` tag with a sha256 hash of its one inline bootstrap script. A meta CSP can't carry `frame-ancestors`, so nginx sends that one as a header. `style-src-attr 'unsafe-inline'` allows `style=""` attributes, which Svelte transitions and CodeMirror set at runtime; CodeMirror's own styles go through constructed stylesheets, which `style-src` doesn't govern.

Imports use package.json subpath imports instead of the `$lib` alias that SvelteKit 3 dropped: `#lib/*`, `#components/*`, `#stores/*`, `#routes/*` and `#test/*`, each with an explicit file extension, such as `#stores/auth.svelte.ts` or `#lib/api/index.ts`. Vite and TypeScript resolve them natively. `tsconfig.json` extends `$app/tsconfig`, which `svelte-kit sync` writes into `node_modules`; `npm run check` and `npm run lint` run the sync first, and `npm install` runs it through `prepare`.

`npm run build` runs `vite build`. The output in `build/` is `200.html`, the content-hashed JavaScript and CSS under `_app/immutable/`, and the files from `static/` (`favicon.png`, `robots.txt`, `sitemap.xml`). Each route is its own chunk, so CodeMirror only loads with the editor. Vite doesn't type-check; the gate is `npm run check`, which runs `svelte-check --fail-on-warnings` in the frontend CI workflow next to `npm run lint` and `npm run build`.

## Serving and local development

`frontend/Dockerfile` has two stages. `node:26-alpine` runs `npm ci` and `npm run build`. `nginx:1.31-alpine` copies `build/` to `/usr/share/nginx/html` and puts `nginx.conf.template` in `/etc/nginx/templates/`, so the image's entrypoint fills in `BACKEND_URL`, `GRAFANA_URL` and `GRAFANA_PUBLIC_URL` with envsubst at startup.

nginx listens on 5001 with TLS, using the certificates cert-generator writes to `frontend/certs`. It proxies `/api/` to `BACKEND_URL` (`https://backend:443` in compose) and gives `/api/v1/events/` SSE settings: no buffering and 24 hour timeouts. `/grafana` is a 302 redirect to `GRAFANA_PUBLIC_URL`. Static assets get a one year `expires`, which is safe since their names carry content hashes, and HTML gets `expires -1` so browsers revalidate it. Any path that isn't a file gets `200.html`, so deep links and reloads work. [Nginx configuration](../operations/nginx-configuration.md) walks through the whole file.

`./deploy.sh dev` starts the compose stack, and the `frontend` service there is the same nginx image on `https://localhost:5001`. It has no source mount, so a frontend change needs `./deploy.sh dev --build` to show up.

`npm run dev` runs the Vite dev server on port 5001 with hot module replacement. It uses HTTPS when `./certs/server.key` and `./certs/server.crt` exist (or `SSL_KEY_FILE` and `SSL_CERT_FILE`), and proxies `/api` to `https://backend:443` without verifying its certificate. The `backend` hostname only resolves inside compose, so API calls only work from a container on `app-network`, with the compose `frontend` service stopped to free the port.
