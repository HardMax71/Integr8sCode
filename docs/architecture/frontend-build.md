# Frontend build

The frontend is a Svelte 5 single-page app that Rollup bundles into `frontend/public/`. nginx serves that folder and proxies `/api/` to the backend, both in production and in the local compose stack. Rollup also has a watch mode with its own small HTTPS server, but it only works from inside the compose network.

## What gets bundled

`src/main.ts` runs once on page load. It calls `initializeApiInterceptors()` from `src/lib/api-interceptors.ts`, which points the generated client at relative URLs with cookies included and registers the error toast and CSRF header interceptors. Then it installs `window.onerror` and `window.onunhandledrejection` handlers that log the error and put it into the `appError` store, and mounts `App.svelte` on `document.body`. If that mount throws, it mounts `ErrorDisplay` instead, so a broken build shows an error page rather than a blank one. See [Error handling](../frontend/error-handling.md) for what happens after that.

`App.svelte` initializes the auth store and renders the router. Routes are a plain array of objects. Protected ones carry `hooks: { pre: requireAuth }`, and admin pages use `requireAdmin`, which runs `requireAuth` and then checks the role. Every page component is an `async () => import(...)` function, so each route ends up in its own chunk and loads on first visit. [Routing](../frontend/routing.md) has the full table.

`src/lib/api/` is generated by `@hey-api/openapi-ts` from `docs/reference/openapi.json`, using the `typescript`, `sdk` and `client-fetch` plugins with Prettier as a post-processor. Don't edit it by hand. After a backend change, `./deploy.sh openapi` rewrites the spec from `create_app()` and `./deploy.sh types` runs `npm run generate:api`. Client configuration and interceptors live in `src/lib/api-interceptors.ts`, outside the generated folder, and callers either pass the result through `unwrap` or `unwrapOr` from the same file or read the generated `{ data, error }` result themselves.

Tailwind v4 is configured in CSS, and there is no `tailwind.config.js`. `src/app.css` imports `tailwindcss`, `styles/components.css` and `styles/pages.css`, loads `@tailwindcss/forms` with the `class` strategy, defines a `dark` variant on the `.dark` class (the theme store toggles it on `<html>`), and declares semantic color tokens such as `bg-default`, `fg-muted` and their `dark-` counterparts in `@theme`.

Shared state lives in rune-based classes in `src/stores/*.svelte.ts`, each exported as a singleton: `authStore`, `themeStore`, `notificationStore`, `userSettingsStore` and `appError`. Toasts come from svelte-sonner, not a store.

## Rollup pipeline

`rollup.config.js` treats the build as production unless `ROLLUP_WATCH` is set, which `npm run dev` does through `rollup -w`. The plugins run in this order:

1. `alias` maps `$lib`, `$components`, `$stores`, `$routes`, `$utils` and `$styles` to `src/`, matching the `paths` in `tsconfig.json`.
2. `replace` swaps exactly one string: `const isProduction = false` in `src/lib/logger.ts`, which drops the consola log level from 4 to 1 in production. There are no other build-time replacements and no `.env` loading.
3. `svelte` compiles components with `runes: true` and `dev` on in watch mode. It preprocesses with `svelte-preprocess` and `globalStyle: false`, because the global style transform would strip the Svelte 5 `:global {}` blocks that svelte-sonner ships its CSS in.
4. `postcss` runs `@tailwindcss/postcss` and then `postcss-lightningcss` (which minifies), and extracts the result to `build/bundle.css`.
5. `typescript` compiles TS, with source maps only in watch mode.
6. `json`, `node-resolve` (browser build, `svelte` export condition) and `commonjs` handle imports from `node_modules`.
7. In production, `cleandir` empties `public/build/` and a small `css-hash` plugin renames the stylesheet to `build/bundle-<hash>.css`.
8. `@rollup/plugin-html` writes `public/index.html` from `src/index.html`, adding a `<link>` for the stylesheet and a `<script nonce="**CSP_NONCE**" type="module">` tag for the entry chunk.
9. In production, `terser` minifies with two compress passes and strips comments. It does not drop `console` calls; the logger level handles noise.

Output is ES modules under `public/`. The entry is `build/main.js` in watch mode and `build/main-<hash>.js` in production, and every other chunk is `build/[name]-[hash].js`. `manualChunks` pins Svelte and the router into `vendor` and the core CodeMirror packages into `codemirror`, so they cache separately from app code. `public/index.html` and `public/build/` are gitignored; only `favicon.png`, `robots.txt` and `sitemap.xml` are checked in.

The `**CSP_NONCE**` placeholder is filled per response by nginx, which uses `$request_id` as the nonce and allows the same value in its `Content-Security-Policy` header:

```nginx
--8<-- "frontend/nginx.conf.template:nonce_injection"
```

Type errors don't fail the Rollup build. `@rollup/plugin-typescript` reports them as warnings, and `tsconfig.json` doesn't set `noEmitOnError`. The gate is `npm run check`, which runs `svelte-check --fail-on-warnings` and is a step in the frontend CI workflow next to `npm run lint` and `npm run build`.

## Serving and local development

`frontend/Dockerfile` has two stages. `node:26-alpine` runs `npm ci` and `npm run build`. `nginx:1.31-alpine` copies `public/` to `/usr/share/nginx/html` and puts `nginx.conf.template` in `/etc/nginx/templates/`, so the image's entrypoint fills in `BACKEND_URL`, `GRAFANA_URL` and `GRAFANA_PUBLIC_URL` with envsubst at startup.

nginx listens on 5001 with TLS, using the certificates cert-generator writes to `frontend/certs`. It proxies `/api/` to `BACKEND_URL` (`https://backend:443` in compose) and gives `/api/v1/events/` SSE settings: no buffering and 24 hour timeouts. `/grafana` is a 302 redirect to `GRAFANA_PUBLIC_URL`. Static assets get a one year `expires`, which is safe since their names carry content hashes, and HTML gets `expires -1` so browsers revalidate it. Unknown paths fall back to `index.html` for client-side routing. [Nginx configuration](../operations/nginx-configuration.md) walks through the whole file.

`./deploy.sh dev` starts the compose stack, and the `frontend` service there is the same nginx image on `https://localhost:5001`. It has no source mount, so a frontend change needs `./deploy.sh dev --build` to show up.

`npm run dev` runs Rollup in watch mode and, after the first write, starts a Node HTTPS server on port 5001 that serves `public/` with an `index.html` fallback. It reads its certificate from `./certs/server.key` and `./certs/server.crt` (or `SSL_KEY_FILE` and `SSL_CERT_FILE`). It proxies `/api` to `https://backend:443` and exits at startup if `/shared_ca/ca.pem` is missing. The proxy loads that CA but also sets `rejectUnauthorized: false`. Since the `backend` hostname and the `shared_ca` volume only exist inside compose, this server works only from a container on `app-network` with that volume mounted, and the compose `frontend` service has to be stopped first to free the port. There is no live reload; refresh the browser after a rebuild.
